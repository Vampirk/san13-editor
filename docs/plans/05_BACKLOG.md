### BUG-03: `SetSwornBrothers`가 인연 리더 헤더를 잘못 덮어씀 [접수]

- `OfficerManager::SetSwornBrothers()`는 의형제 슬롯을 쓴 뒤 헤더 `+0x4A`를 "첫 번째 유효 의형제 ID"로 덮어씁니다.
- 실측(2026-10-14, 전체 2,165 슬롯 읽기 전용 대조): `+0x4A`는 **인연 그룹 리더**로, 대부분 첫 의형제와 같지만 예외가 있습니다 — 유비(610) 헤더 = 610(자기 자신, 의형제 [94, 418]), 손책(359)·주유(241) 헤더 = 359(의형제 슬롯 없음).
- 영향: 에디터에서 유비의 의형제를 편집하면 그룹 리더가 관우(94)로 바뀌는 등 인연 그룹 구조가 변형될 수 있습니다.
- 조치: `+0x4A`의 정확한 의미(리더/단짝 그룹) 규명(RE-01) 후, 리더 무장은 헤더를 유지하는 등 동기화 규칙 교정. 테스트는 규칙 예외 무장이면 쓰기 검증을 SKIP하도록 방어 처리됨.

### BUG-04: 명품 소유권/위치 변경 시 상태 플래그(+0x21) 고정 덮어쓰기 [접수]

- `ItemManager::SetItemOwner()`는 소유 시 `+0x21 = 1`, 몰수 시 `0`, `SetItemLocation()`은 `0`으로 무조건 기록합니다.

### BUG-05: 게임 일자를 시나리오 시작일로 읽음 [완료 — EDGE-60]

- `OfficerManager::GetGameDate()`(EDGE-25/47)는 `RootBase + 0x137A/0x137C/0x1380`을 읽습니다.
- 2026-10-14 실측: 190년 1월 1일 → 1월 12일로 진행한 뒤에도 이 값은 **190/1/1 그대로**이며, `RootBase + 0x141A`(년 u16) / `+0x141C`(월 u8, 0-indexed) / `+0x141D`(일 u8)가 **190/0/12**로 현재 일자와 일치합니다.
- 영향: 상단 일자 뱃지가 시작일로 고정되고, 미등장/사망 판정(`appear_year > 현재 연도`)이 시작 연도 기준으로 이루어져 **몇 년 진행한 세이브에서 이미 등장한 무장이 [미등장]으로 표시**됩니다.
- **2차 확인 (2월 초 진행 후):** `+0x137A`는 여전히 190/1/1 → **시작일 고정 확인**. 그러나 `+0x141A`도 190/0/12에서 변하지 않아 **현재 일자 후보에서 기각** (1월 12일과의 일치는 다른 이벤트 일자로 추정). 모듈 정적 영역(31MB)에서 (년 u16, 월 u8, 일 u8) 및 변형 인코딩 패턴 검색으로도 현재 일자를 찾지 못함.
- **해결 (190/2/1 → 2/5 정적 영역 비교):** `RootBase + 0x6`(uint16)이 30 → 34로 경과 일수와 정확히 일치 (1/1 → 2/1 = 30일 → 한 달 30일 달력). `GetGameDate()`를 '시작일 + 경과 일수'로 교체(`ComputeGameDate()`), 시작일은 `GetScenarioStartDate()`로 분리. 라이브 판독 190년 2월 5일 일치, 오프라인 계산 테스트 6건 추가. 해 넘김(360일) 실측은 아직 없음.

#### 2) 현대화 목표 (초안)

- **에디터 통합:** 별도 실행 파일이 아니라 에디터의 신규 메인 탭(예: 「얼굴 CG」)으로 통합.
- **크로스플랫폼:** 기존 Linux/Windows 듀얼 빌드 체계(`make`, `make win`)에 그대로 포함. 외부 `texconv.exe`·`d3dref9.dll` 의존 제거.
- **무장 편집과 연동:** 무장 상세 모달의 Face ID(`+0x08`, [확정])와 연결하여 "이 무장의 얼굴 보기/교체" 동선 제공.
- **안전성:** 아카이브 수정 전 자동 백업, 원클릭 복원, 변경 이력 표시.

#### 3) 재활용 가능한 기존 자산

- `tools/unpack_s13.py`: S13 ZP1 멀티 청크 아카이브 언패커 (EDGE-40, 1,873개 엔트리 추출 검증).
- Face ID 오프셋 및 실시간 핫패치 검증 (VERIFICATION §3.2, `tools/hotpatch_face.cpp`).
- `PlatformUtil`의 게임/사용자 경로 탐색 추상화.

#### 4) 착수 전 확인 필요 사항 (Open Questions)

1. 얼굴 CG가 저장된 아카이브·엔트리 번호와 텍스처 포맷(DDS 압축 방식, 해상도) 규명.
2. S13 아카이브 **재패킹(압축)** 구현 가능 여부 — 현재는 언패커만 존재. KOEI 압축 포맷 규격 확인 필요.
3. 얼굴 교체 범위: 기존 얼굴 덮어쓰기만 지원할지, 신규 얼굴 슬롯 추가까지 지원할지.
4. 음성 교체 기능의 실제 존재 여부 및 포함 여부.
5. 이미지 입출력 라이브러리 선택 (PNG 디코딩, DDS 인코딩 — 헤더 온리 라이브러리 우선 검토).
6. 원본 도구의 라이선스·재배포 조건 — 코드 참조 없이 포맷 규명만 참고하는 클린룸 방식 권장.
