### BUG-01: 고대무장 관련 기능 오동작 제보 [검증 대기]

- **제보 내용:** "고대무장은 안 되네요" (2026-10-14 접수) → 고대무장 목록 문제로 판단.
- **✅ 핵심 원인 (E) 규명 및 수정 (EDGE-56):** 아래 (E) 참조. 고대무장 목록이 **통째로 비는** 증상의 직접 원인.
- **미확인 사항 (재현 조건 확보 필요):** 증상이 아래 중 무엇인지 확인 필요.
  - (a) 이름이 틀리게 표시됨 / (b) 목록·필터에 안 나옴 / (c) 편집이 인게임에 반영 안 됨 / (d) 고대무장 등장 설정 시 상태(현역/재야/미등장) 오판 / (e) 기타
  - 게임 설정의 「고대무장 등장」 옵션 ON/OFF 여부, 시나리오, 대상 무장 ID.

#### 1차 코드·데이터 조사 결과 (2026-10-14)

**(A) 고대무장 이름 테이블 38/50 불일치 — [실측 확인 → ✅ 2026-10-14 수정 완료, EDGE-55]**

`src/game/OfficerNameTable.cpp`의 하드코딩 배열 `ANCIENT_OFFICER_NAMES[50]`(ID 850~899)을 게임 원본 `pk_1655.tbl`(`OFFICER_NAME_SYSTEM.md` §3 공식: `성 = GetString(6535+ID)`, `명 = GetString(7985+ID)`)으로 디코딩한 값과 대조한 결과, **50개 중 38개가 불일치**합니다. 원본과 일치하는 것은 850~855, 857, 858, 860, 864, 865, 892 12개뿐입니다.

- 코드 테이블에는 게임에 없는 인물(팽월, 번쾌, 관중, 조참, 자산, 상앙, 안영, 사마양저, 백리해, 양대안, **제갈근(삼국시대 인물)**, 고장공, 진승, 오자서, 손무, 곽자의, 척계광, 진경지, 희단, 진량옥, 정성공)이 포함되어 있고, 게임에 있는 인물(유방, 영정, 이신, 웅의, 황헐, 항연, 공수반, 전인제, 전문, 전기, 추기, 조옹, 조승, 극신, 곽외, 위앵, 위무기, 방연, 한무, 한비, 관이오)이 빠져 있습니다.
- **ID 899는 원본 텍스트 테이블에서 이름이 빈 슬롯**인데 코드에는 "곽거병"이 할당되어 있습니다 (원본 곽거병은 862). 단, 라이브 메모리상으로는 899에 능력치(96/91/84/1)를 가진 무장이 존재하므로 정체는 추가 확인 필요.
- `OFFICER_NAME_SYSTEM.md` §4 분류표의 "850~898 (49명), 856 유방, 898 이사"는 **원본과 일치** → 명세서가 맞고 코드 테이블이 틀린 상태.
- 결과적으로 고대무장 대부분이 **엉뚱한 이름으로 표시·검색**되며, 이름으로 찾으면 다른 인물이 편집될 수 있습니다 (증상 (a)·(c)의 유력 원인).

> 원본 기준 공식 명단은 [`specs/OFFICER_NAME_SYSTEM.md`](../specs/OFFICER_NAME_SYSTEM.md) §5.5로 이관되었습니다.

**(B) 출신 분류 필터의 ID 범위 하드코딩 — [B-1 ✅ 수정 완료 (EDGE-56) / B-2 남음]**

`src/ui/OfficerTableView.cpp`의 출신 필터·검색 키워드·`[고대]` 뱃지가 모두 `850 <= id < 900`으로 하드코딩되어 있습니다.

- **(B-1, 완료)** PK 특전 고대/왜국 무장(1251~1263, 예: 한세충·양홍옥·범려·순관)은 **[고대]로 분류되지 않고 [신무장]으로 분류**됩니다. → `IsAncientOfficerId()`(850~899 + 1251~1263)로 필터·검색·뱃지 판별 단일화.
- **(B-2, 남음)** `Created`(신무장) 필터 조건이 `id >= 700 && !(850~899)`이므로 도적/NPC(900~), 이벤트 인물(1048~), **PK 추가 사실무장 100인(1151~1250)까지 전부 [신무장]으로 묶입니다.**

**(C) 900~999 슬롯 해석 충돌 — [미확인]**

- 코드(`GetOfficerKoreanName`)는 900~999를 `editdata_pk.s13` 등록 신무장 인덱스 150~249로 취급합니다.
- 명세서(`OFFICER_NAME_SYSTEM.md` §4)는 900~948을 도적/이벤트 NPC, 970~998을 시설 NPC로 분류합니다 (원본 디코딩 결과도 900 도적왕, 901 도적두목).
- 등록 신무장이 150명을 초과할 때 실제로 어느 슬롯에 배치되는지 인게임 확인 필요.

**(D) 1251~1263 이름 출처 불명 — [미확인]**

- 위 공식으로 `pk_1655.tbl`을 디코딩하면 1251~1263은 모두 빈 문자열입니다. 라이브 메모리에는 13개 슬롯 모두 능력치가 있는 무장이 존재하며, 이 중 1251~1253, 1258~1260 6명은 이름 매핑이 없어 `PK 추가 무장 #ID`로 표시됩니다. 명세서 §4와 코드(`PK_ADDITIONAL_OFFICER_NAMES`)의 1254 한세충 ~ 1263 비미호 매핑은 다른 출처(라이브 메모리 등)일 가능성이 있어 근거 확인 필요.
- 범려가 코드상 881(고대 테이블)과 1256(PK 특전) 두 곳에 존재 → (A) 수정 시 자연 해소 예상.

**(E) 확장 슬롯 VTable 절대 주소 비교로 ID 800+ 전원 로드 실패 — [✅ 2026-10-14 수정 완료, EDGE-56]**

- `OfficerManager::LoadOfficer`가 ID 800 이상 슬롯의 유효성을 VTable **절대 주소** `0x7291c510`으로 검사하고 있었습니다.
- 게임 모듈 로드 베이스는 실행마다 달라질 수 있어(문서 실측 `0x71bb0000` → 2026-10-14 실행 `0x71b90000`), VTable이 `0x728fc510`으로 바뀐 실행에서는 **고대무장(850~)·PK 추가무장(1151~)·자녀 등 ID 800 이상 전원이 로드되지 않아 고대 목록이 0명**이 됩니다.
- 같은 원인으로 주인공 감지(`0x72919c04` 비교)도 실패하여 주인공 카드·소지금 편집이 동작하지 않았습니다.
- 조치: `모듈 베이스 + RVA` 비교(`IsExpectedVTable`)로 교정. 라이브 실측 결과 고대 필터 **0명 → 63명**, 이름·검색 정상, 주인공 감지 복구(현재 세이브: 항적 857).

### BUG-02: 등록 신무장 이름 로더가 첫 번째 신무장만 읽음 [접수]

- `LoadCustomOfficerNames()`는 `EntryBushou` 마커가 무장마다 반복된다고 가정하고 "마커 + 0x20/0x25"에서만 성명을 읽습니다.
- 실측 결과 마커는 **블록 헤더로 1개뿐**이며, 개별 레코드는 `마커 + 0x20`부터 `0x464` 간격으로 이어집니다 (`specs/OFFICER_NAME_SYSTEM.md` §6.1).
- 결과: 등록 신무장이 2명 이상이면 **701번부터 이름이 표시되지 않음** (현재 사용자 파일에는 강월 1명뿐이라 증상이 드러나지 않았음).
- 조치: 레코드 단위 파싱(`0xF660 + k × 0x464`, 빈 레코드 건너뜀)으로 교체하고, 열전(`+0x35`)도 함께 로드. 900~999를 등록 무장 인덱스 150~로 보는 매핑(BUG-01 (C))도 함께 재검토.

### FEAT-02: 게임 프레임 상한 해제 (60 / 120 / 144 / 240 FPS) [접수]

- **요청:** 게임 프레임 상한을 60 / 120 / 144 / 240 FPS 중에서 선택해 올리는 기능.
- **착수 전 확인 필요:**
  1. 게임 내부의 프레임 제한 방식 규명 (프레임 상한 변수, 타이머/Sleep 루프, Present 간격 중 어떤 방식인지) 및 해당 메모리 주소 또는 코드 위치.
  2. 게임 로직(날짜 진행, 전투 속도, 애니메이션)이 프레임에 묶여 있는지 확인. 묶여 있으면 프레임을 올렸을 때 게임 속도까지 빨라지는 부작용이 생길 수 있음.
  3. 적용 방식: 데이터 값 패치로 가능한지, 코드 패치(명령어 수정)가 필요한지. 코드 패치라면 원복 안전성과 버전별 대응 필요.
  4. Proton/DXVK 환경과 Windows 네이티브 환경에서 V-Sync·모니터 주사율과 어떻게 상호작용하는지.
- **UI 초안:** 상단 툴바 또는 설정 탭에 「프레임 상한: 기본 / 60 / 120 / 144 / 240」 선택 + 즉시 적용 / 원복.

- 오프라인 테스트는 게임 메모리를 건드리지 않아야 하므로, 라이브 단계를 분리해 `test_live`로 옮기거나 오프라인 실행 시 부착을 생략하도록 수정 필요.

### TECH-05: 라이브 테스트 세이브 고정 및 실패 시 exit 0 [접수]

- `test_officer_table`은 195년 7월 1일 세이브를 전제로 일자를 검사하여 다른 세이브(예: 190년 1월 1일)에서는 초반에 중단되며, 이때 **FAIL을 출력하고도 exit 0을 반환**합니다 (2026-10-14 확인). 다른 라이브 테스트도 강월(700) 주인공 세이브 등 특정 상태를 전제함.
- 조치: 세이브 의존 단언을 "조건 불일치 시 SKIP"으로 바꾸고, FAIL 발생 시 non-zero exit로 `make`가 실패하도록 수정.

### TECH-06: 분석 도구 VTable 절대 주소 하드코딩 [접수]

- `tools/find_protagonist.cpp`, `tools/find_gold_2000.cpp`, `tools/scan_protagonist_unique.cpp`가 `0x7291c510`을 직접 비교 → 모듈 베이스가 바뀐 실행에서 결과 0건. EDGE-56과 같은 방식(RVA)으로 교정 또는 TECH-03과 함께 도구 정리.

### TECH-07: 미할당 빈 슬롯 목록 노출 [접수]

- 확장 슬롯 로드는 "현재 능력치 > 0"만 검사하므로, status `0xFF`(미할당)이면서 능력치가 1/1/1/1인 빈 슬롯(예: 800~849, 1315~)이 `신무장 / 가상 #ID`로 [신무장] 목록에 대량 노출됨 (2026-10-14 실측: 신무장 필터 1,222명).
- 조치: 출신 필터에서 `status_flag == 0xFF` 슬롯 제외 검토 (B-2와 함께 처리).
