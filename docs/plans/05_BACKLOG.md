## 2. 버그 (BUG)

### BUG-01: 고대무장 관련 기능 오동작 제보 [수정 중]

- **제보 내용:** "고대무장이 안 된다" (2026-10-14 접수).
- **미확인 사항 (재현 조건 확보 필요):** 증상이 아래 중 무엇인지 확인 필요.
  - (a) 이름이 틀리게 표시됨 / (b) 목록·필터에 안 나옴 / (c) 편집이 인게임에 반영 안 됨 / (d) 고대무장 등장 설정 시 상태(현역/재야/미등장) 오판 / (e) 기타
  - 게임 설정의 「고대무장 등장」 옵션 ON/OFF 여부, 시나리오, 대상 무장 ID.

#### 1차 코드·데이터 조사 결과 (2026-10-14)

**(A) 고대무장 이름 테이블 38/50 불일치 — [실측 확인 → ✅ 2026-10-14 수정 완료, EDGE-55]**

`src/game/OfficerNameTable.cpp`의 하드코딩 배열 `ANCIENT_OFFICER_NAMES[50]`(ID 850~899)을 게임 원본 `pk_1655.tbl`(`OFFICER_NAME_SYSTEM.md` §3 공식: `성 = GetString(6535+ID)`, `명 = GetString(7985+ID)`)으로 디코딩한 값과 대조한 결과, **50개 중 38개가 불일치**합니다. 원본과 일치하는 것은 850~855, 857, 858, 860, 864, 865, 892 12개뿐입니다.

- 코드 테이블에는 게임에 없는 인물(팽월, 번쾌, 관중, 조참, 자산, 상앙, 안영, 사마양저, 백리해, 양대안, **제갈근(삼국시대 인물)**, 고장공, 진승, 오자서, 손무, 곽자의, 척계광, 진경지, 희단, 진량옥, 정성공)이 포함되어 있고, 게임에 있는 인물(유방, 영정, 이신, 웅의, 황헐, 항연, 공수반, 전인제, 전문, 전기, 추기, 조옹, 조승, 극신, 곽외, 위앵, 위무기, 방연, 한무, 한비, 관이오)이 빠져 있습니다.
- **ID 899는 원본에서 빈 슬롯**인데 코드에는 "곽거병"이 할당되어 있습니다 (원본 곽거병은 862).
- `OFFICER_NAME_SYSTEM.md` §4 분류표의 "850~898 (49명), 856 유방, 898 이사"는 **원본과 일치** → 명세서가 맞고 코드 테이블이 틀린 상태.
- 결과적으로 고대무장 대부분이 **엉뚱한 이름으로 표시·검색**되며, 이름으로 찾으면 다른 인물이 편집될 수 있습니다 (증상 (a)·(c)의 유력 원인).

> 원본 기준 공식 명단은 [`specs/OFFICER_NAME_SYSTEM.md`](../specs/OFFICER_NAME_SYSTEM.md) §5.5로 이관되었습니다.

**(B) 출신 분류 필터의 ID 범위 하드코딩 — [코드 확인]**

`src/ui/OfficerTableView.cpp`의 출신 필터·검색 키워드·`[고대]` 뱃지가 모두 `850 <= id < 900`으로 하드코딩되어 있습니다.

- PK 특전 고대/왜국 무장(1251~1263, 예: 한세충·양홍옥·범려·순관)은 **[고대]로 분류되지 않고 [신무장]으로 분류**됩니다.
- `Created`(신무장) 필터 조건이 `id >= 700 && !(850~899)`이므로 도적/NPC(900~), 이벤트 인물(1048~), **PK 추가 사실무장 100인(1151~1250)까지 전부 [신무장]으로 묶입니다.**

**(C) 900~999 슬롯 해석 충돌 — [미확인]**

- 코드(`GetOfficerKoreanName`)는 900~999를 `editdata_pk.s13` 등록 신무장 인덱스 150~249로 취급합니다.
- 명세서(`OFFICER_NAME_SYSTEM.md` §4)는 900~948을 도적/이벤트 NPC, 970~998을 시설 NPC로 분류합니다 (원본 디코딩 결과도 900 도적왕, 901 도적두목).
- 등록 신무장이 150명을 초과할 때 실제로 어느 슬롯에 배치되는지 인게임 확인 필요.

**(D) 1251~1263 이름 출처 불명 — [미확인]**

- 위 공식으로 `pk_1655.tbl`을 디코딩하면 1251~1263은 모두 빈 문자열입니다. 명세서 §4와 코드(`PK_ADDITIONAL_OFFICER_NAMES`)의 1254 한세충 ~ 1263 비미호 매핑은 다른 출처(라이브 메모리 등)일 가능성이 있어 근거 확인 필요.
- 범려가 코드상 881(고대 테이블)과 1256(PK 특전) 두 곳에 존재 → (A) 수정 시 자연 해소 예상.

### FUTURE-01: San13PicTool 현대화 및 에디터 통합 [보류 — 착수 전 기록만]

> 버그·기능 개선(②단계) 완료 후 착수합니다. 현재는 방향과 사전 조사 내용만 기록합니다.

#### 2) 현대화 목표 (초안)

- **에디터 통합:** 별도 실행 파일이 아니라 에디터의 신규 메인 탭(예: 「얼굴 CG」)으로 통합.
- **크로스플랫폼:** 기존 Linux/Windows 듀얼 빌드 체계(`make`, `make win`)에 그대로 포함. 외부 `texconv.exe`·`d3dref9.dll` 의존 제거.
- **무장 편집과 연동:** 무장 상세 모달의 Face ID(`+0x08`, [확정])와 연결하여 "이 무장의 얼굴 보기/교체" 동선 제공.
- **안전성:** 아카이브 수정 전 자동 백업, 원클릭 복원, 변경 이력 표시.

#### 3) 재활용 가능한 기존 자산

- `tools/unpack_s13.py`: S13 ZP1 멀티 청크 아카이브 언패커 (EDGE-40, 1,873개 엔트리 추출 검증).
- Face ID 오프셋 및 실시간 핫패치 검증 (VERIFICATION §3.2, `tools/hotpatch_face.cpp`).
- `PlatformUtil`의 게임/사용자 경로 탐색 추상화.

#### 4) 착수 전 확인 필요 사항 (Open Questions)

1. 얼굴 CG가 저장된 아카이브·엔트리 번호와 텍스처 포맷(DDS 압축 방식, 해상도) 규명.
2. S13 아카이브 **재패킹(압축)** 구현 가능 여부 — 현재는 언패커만 존재. KOEI 압축 포맷 규격 확인 필요.
3. 얼굴 교체 범위: 기존 얼굴 덮어쓰기만 지원할지, 신규 얼굴 슬롯 추가까지 지원할지.
4. 음성 교체 기능의 실제 존재 여부 및 포함 여부.
5. 이미지 입출력 라이브러리 선택 (PNG 디코딩, DDS 인코딩 — 헤더 온리 라이브러리 우선 검토).
6. 원본 도구의 라이선스·재배포 조건 — 코드 참조 없이 포맷 규명만 참고하는 클린룸 방식 권장.
