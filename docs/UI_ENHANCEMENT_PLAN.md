## 1. 개요 및 목적
코어 도메인 레이어(전법, 인연, 세력, 부락 요충지, 명품 아이템) 구현이 완료됨에 따라, 실사용 중 발견된 **핵심 기능 버그 2건을 긴급 수정**하고, 사용자가 제안한 **신규 편의 기능(미소유 보물 소재 도시 표시)** 및 **반응형 UI(창 크기에 따른 유동적 레이아웃/글자 조절)**를 체계적으로 적용하기 위한 전면 개선 계획을 수립합니다.

또한, 개발 과정에서 누적된 루트 디렉토리의 임시 파일들을 정리하고 Git 체크포인트를 수립하여 안전한 개발 환경을 유지합니다.

## 2. 사용자 피드백 및 사전 메모리 실측 분석 결과

### [BUG-01] 시나리오 일자 표출 오류 (195년 7월 1일 $\rightarrow$ 1월 1일 고정)
- **현상**: 인게임 날짜가 195년 7월 1일임에도 불구하고 에디터 상단 바에 항상 "195년 1월 1일"로 고정 표출되는 문제.
- **원인 규명**:
  - `src/game/OfficerManager.cpp`의 `GetGameDate()`에서 다음과 같이 오프셋을 읽고 있었음:
    ```cpp
    m_driver->Read<uint16_t>(m_rootBase + 0x137A, y); // 년
    m_driver->Read<uint16_t>(m_rootBase + 0x1380, m); // 월 (오류!)
    m_driver->Read<uint16_t>(m_rootBase + 0x1386, d); // 일 (오류!)
    ```
  - **실측 라이브 메모리 덤프 (`0x73B6C5D8 + 0x1370 ~ 0x1390`)**:
    ```text
    +0x137A: C3 00 -> 195 (년)
    +0x137C: 06 00 -> 6 (월: 0-indexed! 0=1월, 6=7월 -> +1 필요)
    +0x1380: 01 00 -> 1 (일: 1일)
    ```
  - `+0x1380`에 있던 '1일'을 '월'로 읽어버렸기 때문에, 날짜가 1일인 경우 항상 1월로 나타났고, 1-11월(0~5)이 완전히 누락되고 있었음.
- **해결 방안**:
  - 년: `RootBase + 0x137A` (uint16_t)
  - 월: `RootBase + 0x137C` (uint16_t, 0~11 $\rightarrow$ `+ 1` 하여 1~12월로 변환)
  - 일: `RootBase + 0x1380` (uint16_t, 1~30)

### [BUG-02] 도시 자원편집기 건물 요새화 인게임 미반영 버그
- **현상**: `CityDetailModal`에서 부락 요새화(견진/군악대/요양사/병량고/방채)를 선택해도 게임 지도/인게임 엔진에 전혀 반영되지 않는 문제.
- **원인 규명**:
  - 기존 `SettlementManager::FortifySettlement()`는 바닐라 28B 구조체(`San13SettlementRaw`)의 사용되지 않는 4B 패딩(`tail_pad`)에만 값을 쓰고 있었음.
  - 삼국지 13 PK의 요충/성채/레벨 진짜 데이터는 **`CChiiki` (`RootBase + 0xD31A10`, 20B Stride, 총 2,500개)** 배열에서 관리됨.
  - `scratch_test_cchiiki_write.cpp`에서 검증된 바와 같이, `site_id = 60 + settlement_id` 위치의 `CChiiki`에 쓰기 작업이 누락되어 있었음.
- **해결 방안**:
  - `SettlementManager`에 `CChiiki` 베이스 주소(`RootBase + 0xD31A10`)를 등록.
  - `FortifySettlement()` 및 `DemolishFortress()` 시 `CChiiki`의 `+0x06 (force_id)`, `+0x07 (jousai_type)`, `+0x08 (hp)`, `+0x10 (level)`을 직접 기록하고 동기화하도록 전면 교정.

### [FEAT-01] 명품 아이템 편집기 미소유 보물 시장 위치 조사 및 표시
- **요청 사항**: 무장이 소유하지 않은 명품이 어느 도시의 시장(상점)에 있는지 위치 표출 가능 여부 조사.
- **실측 조사 결과**: **100% 규명 완료 (표출 가능!)**
  - 36B `CItem` 구조체 실측 덤프 결과:
    - `+0x1C` (uint16_t): 소유 무장 ID (`0xFFFF` = 미소유)
    - `+0x20` (uint8_t): **소재 도시 ID (0 ~ 59)**
      - 무장이 소유 중일 때: `0xFF (255)`
      - 미소유 상태일 때: 낙양(23), 장안(25), 허창(34), 업(16) 등 해당 도시 ID 기록됨!
      - 예: 참사검(15) $\rightarrow$ 낙양(23), 간장검(20)/막야검(21) $\rightarrow$ 회계(54)
    - `+0x21` (uint8_t): 아이템 상태 플래그 (1=무장 장비, 0=시장/미발견 재야)
- **해결 방안**:
  - `CItem` 구조체 및 `ItemRecord`에 `location_city_id` 필드 공식 추가.
  - `ItemTableView`의 "소유 무장" 컬럼에 미소유인 경우 `[낙양] 시장` 형태로 소재 도시명을 연동 표출.
  - 도시별 미소유 보물 검색/필터 드롭다운 추가.

### [UI-01] 반응형 UI 및 유동적 글자/레이아웃 조절 (Responsive UI)
- **요청 사항**: 에디터 창 크기 조절 시 글자와 UI 요소들이 찌그러지거나 잘리지 않고 유동적으로 최적화되는 반응형 구조.
- **해결 방안**:
  1. **고정 픽셀 지양 및 상대 비율 기반 레이아웃**:
     - `ImGui::GetContentRegionAvail().x`를 기준으로 테이블 컬럼 너비 동적 분할 (`ImGuiTableColumnFlags_WidthStretch`).
  2. **DPI 및 윈도우 스케일링 대응**:
     - 창 크기 변화에 연동하여 `ImGui::GetIO().FontGlobalScale` 또는 고해상도 폰트 아틀라스 재빌드 지원.
  3. **모달 윈도우 반응형 제약**:
     - 무장/도시 상세 모달 크기를 고정치(`820x580`) 대신 뷰포트 대비 비율(예: 너비 80%, 높이 85%) 및 최소/최대 제약 적용.
