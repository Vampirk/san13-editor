# 삼국지 13 PK (San13PK Korean v1.0.2) 메모리 오프셋 및 구조체 규명 명세서

> **최종 갱신일:** 2026-10-14  
> **기준 환경:** Linux x86_64, Valve GE-Proton, San13PK_kr.exe (32-bit PE)  
> **실측 시나리오:** 190년 1월 1일 반동탁 연합군  
> **검증 기준:** 실시간 `/proc/$PID/mem` 읽기/쓰기 및 인게임 무장 정보창 실측 대조  

---

## 1. 검증 수준 정의 (Verification Levels)

본 문서의 모든 오프셋 및 구조체 필드는 아래 3단계 검증 수준으로 분류하여 표기합니다:

- **[확정]**: 실시간 프로세스 메모리 주소 확인, 에디터 쓰기 후 인게임 UI 반영 확인, 다수 무장 교차 검증 및 단위 테스트 완료.
- **[유력]**: 메모리 덤프 패턴 및 레거시 반에디터 RVA 대조를 통해 오프셋 특정 완료, 단 일부 시나리오/특수 상황에서 추가 관찰 필요.
- **[미확인]**: 오프셋 범위는 특정되었으나 구체적인 비트 플래그 정의 또는 엔진 내 용도가 완전히 규명되지 않음.

## 2. 루트 베이스 주소 산출 공식 [확정]

게임 바이너리의 PE 헤더 `TimeDateStamp`를 검사하여 전역 데이터 루트 주소(`RootBase`)를 산출합니다.

- **타깃 프로세스:** `San13PK_kr.exe` / `SAN13PK.exe` (PE32 x86)
- **산출식:** `RootBaseAddress = Proton WoW64 Base + Global Base Offset`

## 4. 무장 데이터 상세 구조 (`San13OfficerHeader` - 4,796 B, Stride: `0x12BC`)

- **무장 주소 계산식:** `OfficerAddress = RootBase + 0x015EE0 + (OfficerID * 0x12BC)`
- **헤더 크기:** 80바이트 (`+0x00 ~ +0x4F`)

### 4.1. 기본 식별 및 헤더 필드 (`+0x00 ~ +0x14`)

| 오프셋 | 타입 | 필드명 | 설명 | 검증 수준 | 실측 표본 / 검증 상세 |
| :---: | :---: | :--- | :--- | :---: | :--- |
| `+0x00` | `uint32_t` | `vtable` | VTable 포인터 (`0x7291c510`) | [확정] | 유효 무장 슬롯 식별자 (확장 슬롯 검증에 사용) |
| `+0x04` | `uint32_t` | `officer_id` | 고유 무장 번호 (0 ~ 2164) | [확정] | 본인 무장 ID |
| `+0x08` | `uint16_t` | `face_id` | 얼굴 CG 번호 (Face ID) | [확정] | 조조 405 $\leftrightarrow$ 관우 117 실시간 핫패치 검증 완료 |
| `+0x0A` | `uint16_t` | `city_id` | 부임/거점 도시 번호 (0 ~ 59, 0xFF=미배치/군주/일반) | [확정] | **한계 검증 완료(Step 4)**: 전수 조사 결과 800명 중 33명(태수/거점 관리자)만 0~59를 가지며, 767명(95.8%)은 `0xFF`로 비어 있어 **도시별 인물 역색인 용도로는 불완전함**이 실측 확인됨. |
| `+0x0C` | `uint8_t` | `rank` | 품관 (0:군주, 1~9: 1~9품관) | [확정] | 9품관 체계 및 군주 식별 실측 검증 완료 |

| `+0x14` | `uint8_t` | `unknown_14` | 미확인 플래그 | [미확인] | 상태/내부 플래그 추정 |

## 6. 폐기된 초기 가설 목록 (Historical Hypotheses Retired)

역분석 과정에서 초기 추측 후 실측 검증을 통해 폐기 및 대체된 오프셋 목록입니다. 과거 문서나 로그 열람 시 혼선을 방지하기 위해 기록을 보존합니다.

1. **`+0x3E` 오프셋:**
   - *초기 가설:* 무장 오브젝트 내부 인덱스 ID.
   - *실측 결과:* 소속 군주 무장 ID(`lord_officer_id`)로 확인됨 (본인이 군주면 본인 ID와 일치, 조조 휘하 장수는 333으로 일치, EDGE-31).
2. **`+0x4A` 오프셋:**
   - *초기 가설:* 소속 세력/군주 번호.
   - *실측 결과:* 의형제/단짝 리더 무장 ID(`sworn_brother_id`)로 확인됨. 실제 세력 번호는 `+0x3C`(`force_id`)임 (EDGE-23).
3. **`+0x53`, `+0x56` 오프셋:**
   - *초기 가설:* 보유 전법 수 및 전법 계열 유형.
   - *실측 결과:* 음주/주량(`+0x53`: 0금주, 1보통, 2대음) 및 가치관 용애(`+0x56`: 0~4)로 확인됨 (Step 6.0-4).
4. **특기 개수:**
   - *초기 가설:* 삼국지 13 오리지널 기반 14대 특기.
   - *실측 결과:* PK 기준 20대 특기 (`+0x26 ~ +0x39`, 농업~귀모 각 1바이트씩 연속 매핑)로 확인됨.
5. **`+0x0A` 무장 소재 도시 역색인:**
   - *초기 가설:* 전 무장이 실시간으로 위치한 도시 ID (0~59)가 저장되어 있어 도시별 인물을 전원 역색인 가능.
   - *실측 결과:* 800명 역사무장 전수 조사 결과, 태수/거점 관리자 등 33명만 0~59를 가지며 95.8%(767명)는 `0xFF(255)`로 기록되어 있어 단순 `+0x0A` 검색으로는 도시별 소속 인물을 전원 파악할 수 없음이 확인됨 (Step 4 검증). 도시 구조체 카운트(`+0x144` 등) 및 세력 연동 대안으로 전환.
6. **인구(Population) 단일 메모리 저장 가설:**
   - *초기 가설:* 도시 368바이트 내 또는 외부 청크에 화면에 보이는 총 인구(예: 97,120 / 222,200)가 단일 4바이트 정수로 직접 저장되어 있을 것이다.
   - *실측 결과:* 전 프로세스 메모리 스캔 결과 총 인구 수치는 단일 정수로 존재하지 않으며, 실제로는 `+0x60`(기초 민간 인구)과 `+0x64`(주둔 병력)을 게임 엔진이 렌더링 시 실시간 합산하여 화면에 표출하는 공식임이 양평(95,000 + 2,120 = 97,120) 및 금성(200,000 + 22,200 = 222,200) 2개 도시에서 100% 일치로 검증됨 (Phase 2 검증).
7. **도시 부락 성채 요새화 tail_pad 쓰기 가설:**
   - *초기 가설:* 도시 구조체(+0x158 tail_pad) 또는 부락 레코드 내의 단순 플래그 바이트 쓰기로 성채가 건축될 것이다.
   - *실측 결과:* 인게임 요새화는 `CChiiki` (`RootBase + 0xD31A10`, Stride 20B) 배열의 `+0x07` (jousai_type), `+0x08` (hp), `+0x10` (level)에 직접 기록해야만 인게임 맵상에 견진/방채 그래픽 및 내구도가 온전히 반영됨이 실측 확인됨 (EDGE-48).
8. **시나리오 일자 +0x1380 '월' 오독 가설:**
   - *초기 가설:* `RootBase + 0x1380`이 '월'이고 `+0x1386`이 '일'일 것이다.
   - *실측 결과:* `+0x1380`은 1일(시나리오 개시일)의 '일(Day)'이었으며, 실제 '월(Month)'은 `+0x137C`에 0-indexed(0=1월, 6=7월)로 저장되어 있어 7월 1일 시나리오가 1월 1일로 고정 표출되던 원인이 규명됨. `+0x137A` (년), `+0x137C` (월 = raw + 1), `+0x1380` (일)로 교정 완료 (EDGE-47).
9. **VTable 절대 주소 고정 비교 가설:**
   - *초기 가설:* 무장 VTable은 항상 `0x7291c510`, 주인공 VTable은 항상 `0x72919c04`이므로 절대값으로 유효 슬롯을 판별할 수 있다.
   - *실측 결과:* 모듈 로드 베이스가 `0x71b90000`으로 바뀐 실행에서 VTable이 `0x728fc510` / `0x728f9c04`로 이동하여, ID 800 이상 확장 슬롯(고대무장·PK 추가무장·자녀 등) 전체와 주인공 감지가 무효 판정되는 버그 발생. 모듈 상대 주소(RVA) 비교로 교정 (EDGE-56, §2.1).
10. **등록 무장 청크 16 오프셋 `+0xD3DD50` 가설:**
   - *초기 가설:* 등록 무장 & 인연 배열(0x424 B × 1,015)이 `RootBase + 0xD3DD50`에 위치한다.
   - *실측 결과:* 해당 위치에는 VTable 배열이 없으며, 실제 배열은 `RootBase + 0xC2AF34`(VTable RVA `0xD6C3F8`)에서 확인됨. 두 위치 모두 모듈 정적 영역이므로 실행 간 변동이 아닌 기록 오류로 판단 (2026-10-14, `OFFICER_NAME_SYSTEM.md` §6.2).
