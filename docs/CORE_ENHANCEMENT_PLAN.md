1. **순차적 1단계씩 진행:** 한 번에 무리하게 변경하지 않고, 한 단계씩 구현 -> 단위 테스트/인게임 검증 -> 커밋/확정 후 다음 단계로 이행.

3. **완료 후 GUI 전면 개편 진입:** 본 5대 작업 완료 직후 전면적인 UI/UX 디자인 개선 착수.

### [Phase 2] 복수 인연(의형제/친애/원수) 연동
- **현상:** 의형제는 최대 3명, 원수/친애도 여러 명 지정 가능하나 현재 1명만 표시됨.
- **원인:**
  - 기존 구조체(`San13OfficerHeader`)가 `+0x4A`(의형제 1명), `+0x4C`(원수 1명)만 단일 필드로 정의됨.
- **실측 메모리 구조 (`Offset +0x1280 ~ +0x12BC`):**
  - `+0x1284 ~ +0x128E`: 친애 무장 uint16 슬롯 배열 (유비/관우/장비 -> 제갈량 283 등)
  - `+0x1296, +0x1298, +0x129A`: **의형제 3인 uint16 슬롯 배열** (0xFFFF/0=공백)
  - `+0x129C ~ +0x12A0`: 원수/혐오 무장 uint16 슬롯 배열
- **구현 내용:**
  1. `Officer.hpp` 무장 데이터 구조체에 다중 인연 슬롯 확장 정의.
  2. `OfficerDetailModal` 4번째 탭(관계/인연)의 UI를 개편하여 의형제 1/2/3번, 친애 목록, 원수 목록을 각각 개별 슬롯 또는 다중 리스트로 표시 및 편집 지원.

### [Phase 3] 세력 실명화 매핑 ("세력 6" -> "조조군", "원소군") & 부락 지배 세력 정상화
- **현상 1:** 무장 상세 및 도시 목록에서 단순 숫자(세력 6) 대신 실명(조조군) 표출 필요.
- **현상 2 (사용자 제보):** 부락 테이블에서 북평에 도겸군, 남피에 유표군, 제북에 마등군 등 엉뚱한 세력명이 나오는 버그 발생.
- **근원 원인 전수 분석 (Root Cause):**
  1. `San13SettlementRaw`의 오프셋 `+0x06`은 세력 번호(`force_id`)가 아니라 **부락 효과 타입(`default_effect_id`)**이었음.
     - 값 0 (상업 소 35개) ➔ Force 0 (조조군)으로 오인
     - 값 3 (농업 소 35개) ➔ Force 3 (마등군)으로 오인
     - 값 6 (병역 소 17개) ➔ Force 6 (유표군)으로 오인
     - 값 18 (지휘 소 14개) ➔ Force 18 (도겸군)으로 오인 등.
  2. 삼국지 13 시스템상 **부락은 자체 소속 세력 필드가 없으며, 관할 도시의 지배 세력에 완전히 종속**됨.
     - 미장악(개발도 < 100% 또는 `primary_city_id == 0xFF`): **"미종속 (중립)"**
     - 장악 완료(개발도 == 100%): **해당 도시의 지배 세력(`City + 0x3E` 군주 기반)** 소유.
  3. 도시 지배 군주 오프셋 실측 규명 완료:
     - `City + 0x3E` (uint16_t): 도시 태수/군주 무장 ID (양평 176 공손도, 북평 174 공손찬, 남피 18 원소, 진류 333 조조, 낙양 480 동탁, 허창 65535 공백지).
- **해결 방안 및 구현 내용:**
  1. `Settlement.hpp`: `San13SettlementRaw`의 `+0x06` 필드를 `default_effect_id`로 정정.
  2. `City.hpp` & `CityManager`: 도시 구조체에 `ruler_id` (`+0x3E`) 읽기 지원 추가.
  3. `SettlementManager`: 부락 로드 시 개발도와 관할 도시 군주를 검사하여:
     - 개발도 < 100% 또는 공백지 ➔ `force_name = "미종속 (중립)"`, `force_id = 0xFFFF`
     - 개발도 == 100% ➔ 관할 도시 군주의 세력명(`ForceManager::GetForceName` 또는 `[군주명]군`) 부여.
  4. `CityDetailModal`: 부락 테이블에 위 룰을 적용하여 100% 장악 부락만 해당 도시의 세력명으로 황금색 표출, 미장악 부락은 회색 '미종속 (중립)'으로 표출.
  5. 도시 상세 모달 헤더에도 도시의 실제 지배 세력명 및 군주명 표출.

### [Phase 4] 부락 및 요새(진/보루) 전환 반영 (완료)
- **현상:** 삼국지 13 PK의 핵심 전략 요소인 '요충(要衝)' 및 '성채/요새(진/보루/성채/군악대)' 시스템을 구분하거나 반영하지 못하고 단순 부락으로만 취급됨.
- **심층 메모리 및 시스템 실측 분석 결과:**
  1. **슬롯 체계 (`RootBase + 0x0CA48`, Stride 28B, 총 300개):**
     - `0 ~ 146` (147개): 고정 맵 부락 및 요충지 (전토 147개 지명 100% 매핑 완료).
     - `147 ~ 299` (153개): PK 동적 요새/진지 슬롯. 미사용 시 `default_effect_id = 255`, `is_active = 255`. 출병 부대가 야전에 진지를 구축할 때 동적 할당됨.
  2. **부락 등급 및 요충 체계 (`default_effect_id`, 0 ~ 21 총 22종):**
     - 0~2: 상업 부락 (소 Lv1 / 중 Lv2 / 대 Lv3)
     - 3~5: 농업 부락 (소 Lv1 / 중 Lv2 / 대 Lv3)
     - 6~8: 병역 부락 (소 Lv1 / 중 Lv2 / 대 Lv3)
     - 9~14: 특수병과 요충 (궁기병 / 청주병 / 호표기 / 동주병 / 서량병 / 등갑병)
     - 15~17: 사기 거점 (소 Lv1 / 중 Lv2 / 대 Lv3)
     - 18~20: 지휘 거점 (소 Lv1 / 중 Lv2 / 대 Lv3)
     - 21: 상병 거점
  3. **요새화 / 개축(改築) 시설 체계:**
     - `일반 부락 (None)`: 내정 버프 제공형 기본 거점
     - `견진 (堅陣, Lv1)`: 기본 방어 진지 (내구도 1,000)
     - `보루 (砦, Lv2)`: 강화 방어 진지 (내구도 2,000)
     - `견채 (堅砦, Lv3)`: 상급 방어 요새 (내구도 3,000)
     - `성채 / 방채 (防砦, Lv4~5)`: 최상급 결전 요새 (내구도 4,000 ~ 5,000)
     - `군악대 (軍樂臺)`: 사기 지속 회복 지원 시설
     - `치료원 (療養舎)`: 부상병 지속 회복 지원 시설
- **구현 내용:**─
  1. `Settlement.hpp`:
     - `FortressType` (None, Camp[진], Fortress[보루], Stronghold[성채], MusicTower[군악대], Hospital[치료원]) Enum 정의.
     - `SettlementRecord`에 `fortress_type`, `type_tag` (`[부락]`, `[진]`, `[보루]`, `[성채]` 등), `hp`, `max_hp`, `is_fortified` 필드 추가.
  2. `SettlementManager.cpp`:
     - 부락 로드 시 요새화 상태 및 거점 태그 판정 로직 연동.
     - `FortifySettlement()`: 부락을 진/보루/성채 등으로 즉시 개축 및 내구도 설정 API 구현.
     - `DemolishFortress()`: 요새를 일반 부락으로 원복하는 API 구현.
     - `FortifyAllCitySettlements()`: 해당 도시의 모든 관할 부락을 일괄 [보루] 요새화하는 원클릭 치트 API 구현.
  3. `CityDetailModal.cpp`:
     - 부락 테이블 컬럼에 `거점 유형` 뱃지 (`[부락]`, `[진]`, `[보루]`, `[성채]`) 추가.
  5. **사용자 피드백 기반 심층 보완 (부락 건물 미반영 및 최대 건물 Lv 미적용 해결):**
     - **원인 1 (`primary_city_id` +0x13 미갱신)**:
       - 장악도 바이트(`city_dev_progress`)만 100으로 쓰고 `primary_city_id`를 갱신하지 않아 인게임 엔진이 여전히 "중립(255)"으로 판정하여 지배권 및 건물 건축을 불허함.
       - ➔ **해결**: 장악도 100% 또는 건물 건축 시 `primary_city_id = cityId` 강제 기록 및 0% 시 `0xFF` 초기화.
      - **원인 2 (핵심 규명: 바닐라 부락 패딩 vs PK 진짜 요새/성채 구조체 CChiiki 분리)**:
        - **현상:** 에디터에서 요새를 건축/변경해도 인게임 지도에 전혀 반영되지 않음.
        - **근본 원인 실측 규명:**
          - 기존 코드는 `San13SettlementRaw` (RootBase + 0x0CA48, 28B)의 끝부분 `tail_pad`에 요새 데이터를 기록했으나, 이는 바닐라 부락 구조체의 무효 패딩일 뿐 게임 엔진은 이를 읽지 않음.
        - **라이브 메모리 및 함수 어셈블리(`0x71c8626b`, `0x72495120`) 정밀 역추적 결과:**
          - PK 요충/성채/레벨의 진짜 데이터는 **`CChiiki` (RootBase + 0xD31A10, Stride: 20B, 총 2,500개)** 배열에 완전 격리되어 관리됨.
          - VTable: `0x7291c320` (`.?AVCChiiki@@`)
          - **노드 ID 매핑 규칙:**
            - 도시 60개: `site_id = 0 ~ 59`
            - **부락 147개: `site_id = 60 ~ 206` (`site_id = 60 + settlement_id`)**
            - 기타 관문/야전 거점: `site_id = 207 ~ 2,499`
          - **`CChiiki` 구조체 레이아웃 (Stride: 20B):**
            - `+0x00` (uint32_t): VTable (`0x7291c320`)
            - `+0x04` (uint16_t): 지역 노드 번호 (`site_id`, 0 ~ 2,499)
            - `+0x06` (uint8_t): **성채 소유 세력 ID (`force_id`)** (중립/미건설: `0xFF`)
            - `+0x07` (int8_t): **성채 종류 ID (`jousai_type`)**
              - `-1 (0xFF)`: 건물 없음 (일반 부락/요충)
              - `0`: 진 (陣, 기본 내구 1000 / 실측 배치 500)
              - `1`: 견진 (堅陣, 기본 내구 2000 / 실측 배치 600~750)
              - `2`: 보루 (砦, 기본 내구 3000)
              - `3`: 견채 (堅砦, 기본 내구 4000 / 실측 배치 1000~1250)
              - `4`: 방채/성채 (防砦, 기본 내구 5000)
            - `+0x08 ~ +0x09` (uint16_t): **성채 현재 내구도 (`hp`)** (미건설 시 `0xFFFF`)
            - `+0x0A ~ +0x0C` (3B): 패딩 (`0xFF, 0xFF, 0xFF`)
            - `+0x0D ~ +0x0F` (3B): 제로 패딩 (`0x00, 0x00, 0x00`)
            - `+0x10` (uint8_t): **현재 요충 레벨 (`level`, 0 ~ 5)** (인게임 지도에 표시되는 요충 등급!)
            - `+0x11 ~ +0x13` (3B): 제로 패딩 (`0x00, 0x00, 0x00`)
